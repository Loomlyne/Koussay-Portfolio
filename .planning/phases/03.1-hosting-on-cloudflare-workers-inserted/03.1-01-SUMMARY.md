## Round-2 dashboard scope that now binds Plans 04, 09, 11, 12, 13

The authoritative list, with the D1 field each feature reads, is the "New in this round" section of `.media-probe/admin-design/index.html`. In short:

- **Shell:** UI System sidebar app shell on every admin page (Overview, Bookings {n}, Drafts {n}, Blocked time; signed-in email and Sign out at the bottom). Collapses to a top bar + menu drawer below 900px. Active nav count is an outline badge (solid black stays reserved for New and Block time).
- **Overview (`/admin`, new home):** tiles Calls in the next 7 days · New — needs your eye (oldest booked time) · Bookings this month vs the same days of last month · Started bookings that finished (last 30 days, % with both counts). Next call card (countdown, both times, research summary + talking points, Open booking / Email them / Website ↗). This week strip (calls and blocks, Dubai time). Charts: bookings per week (12 weeks, current week lighter), Help with (multi), Budget (bands). Recent activity, last 7 days.
- **Bookings list (moves to `/admin/bookings`):** search (name, email, company), Status and Help with filters, sort When / Booked on, all in the URL so it works without JS; result count and Clear filters; Research column (Done / Running / Failed / None); Export CSV of the current view (behind Access, `private, no-store`). Upcoming/Past/Cancelled/All tabs kept.
- **Booking detail:** initials avatar + status badge; quick actions Email them / Copy email / Website ↗ / Open file; two columns on desktop (main: Call, Contact, Project, Research briefing; side: Status, Timeline, Emails); private "Your note" (label "Only you see this.", Save note, "Saved."). Status card first on phone.
- **Drafts:** "Stopped at" filter (All / Contact = steps 1-3 / Day and time = 4-5 / Project = 6-11) with counts, search, step bar.
- **Blocked time:** signed form (branded pickers) and remove-confirm unchanged.
- **New copy and empty states:** as listed in the sheet.

### New data this needs (for the schema plan)

1. `bookings.admin_note` TEXT NULL — saved by POST `/admin/api/bookings/<id>/note`, never emailed.
2. `booking_events` table (id, booking_id, at, kind, from_status, to_status) — written by the status and cancel routes; read by Timeline and Recent activity.
3. `blocks.created_at`.
4. Draft deleted or flagged when its booking is created (finish rate must not double-count). Notion imports have no drafts; the rate is meaningful from the switch on.
5. Research briefing written time stored (already shown in round 1: "Written 5 Oct, 11:43").
6. Activity uses the draft's last change ("stopped at {step} (draft)"); no `drafts.created_at` needed.

## Deviations from the UI-SPEC picture table (accepted with the signature)

- Picture 1 renders the All view (Upcoming never shows Cancelled, so it cannot hold all four statuses).
- Draft step labels follow `lib/book/steps.js` ("Step 9 of 11 · Budget"), not the spec's example "Step 6".
- Sample visitor times use correct offsets (round 1 had London one hour off for October).
- Round 2 sidebar breakpoint is 900px (the spec's 640px still governs phone cards).
