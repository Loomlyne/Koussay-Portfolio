**Gathered:** 2026-10-04
**Status:** Ready for planning

<decisions>
## Implementation Decisions

### How Koussay sees and manages bookings
- **D-01:** Both channels. Every finished booking emails Koussay as today, now with an `.ics` calendar invite attached so it lands in his phone calendar. A private `/admin` page also lists every booking.
- **D-02:** Blocked time is set on `/admin` only: pick a whole day or a time range, saved to D1, and those slots disappear from the booking form's availability. No external calendar feed.
- **D-03:** On `/admin` Koussay can read every field of a booking and change its status (New, Confirmed, Done, Cancelled). Cancelling frees the slot and sends the visitor a Resend email saying the call is cancelled. No other email goes out from `/admin`. No delete button.
- **D-04:** `/admin` (and any admin API) is behind Cloudflare Access with an email one-time code, allowing only Koussay's address. No password in the app. The Worker also verifies the Access JWT on every admin request, so a missing Access policy fails closed. Koussay gives the allowed email address at the Access setup step.
- **D-05:** Design before code: the `/admin` list, booking detail, block-time view, the cancel email and the `.ics` invite are shown to Koussay as pictures and signed before they are coded. The cancel email wording is his to approve; nothing is invented.

### Existing Notion data
- **D-06:** A one-off local script imports every real Notion booking into D1 (name, email, date and time, timezone, company, website, services, budget, deadline, details, status, research briefing). Drafts and test rows are skipped. The script reads Notion keys from `.env.local` through `scripts/lib/load-env.mjs`; Claude never reads or types them.
- **D-07:** Notion blocked-time calendar is not imported. D1 blocks start empty; Koussay re-blocks days on `/admin` after the switch.
- **D-08:** Files attached to old Notion bookings are downloaded once by the import script and stored in the private R2 bucket, linked from the booking on `/admin` (Notion file URLs expire, so this is the only chance).
- **D-09:** The import is idempotent (keyed by Notion page id): it runs once early for testing, then again right before the DNS switch to catch bookings made on Vercel in between. No booking freeze.

### New attachments, drafts, research
- **D-10:** New attachments go to a private R2 bucket (not `koussay-media`, never on media.koussay.online). `/admin` links to them through the Worker behind Access. The owner email still attaches the file as today.
- **D-11:** Drafts (half-finished bookings with the last step reached) keep being saved, now in D1, and the draft notice email stays. `/admin` lists drafts separately from bookings.
- **D-12:** AI research keeps running after a booking, as today (`lib/book/research.js`), and the briefing is saved on the booking in D1, readable on `/admin`. OpenAI, Gemini and Firecrawl keys become Worker secrets.
- **D-13:** Retention: drafts that never become a booking are deleted automatically after 90 days (scheduled Worker). Finished bookings and their files are kept.

### Cut-over
- **D-14:** The full site, booking included, is tested on the `workers.dev` address against the real D1 and R2. Koussay books once there and confirms D1 row, both Resend emails and the invite; then approves the DNS switch in the question form. Vercel keeps serving koussay.online until then.
- **D-15:** Fix forward only. No planned DNS switch-back to Vercel. Vercel stays deployed and untouched for the week, then is removed (PLAT-01).
- **D-16:** Vercel Speed Insights is replaced by Cloudflare Web Analytics (cookie-free, page views and Core Web Vitals). `@vercel/speed-insights` is removed.

### Claude's Discretion
- Adapter: OpenNext for Cloudflare vs vinext, Wrangler config, preview setup, image optimisation without Vercel (gallery uses `next/image` with the R2 host).
- D1 schema (tables, indexes, status values as stored), migrations folder, and the slot-claim approach that replaces the per-instance pending-slot cache.
- Private bucket name, object key scheme, and file size cap (keep today's `MAX_ATTACHMENT_BYTES`).
- `.ics` details (UID, organizer, timezone handling) within D-01 and the signed picture.
- Whether `workers.dev` stays enabled after the switch (if it stays, it must send `noindex` or redirect to koussay.online).
- How the `/admin` pages are built (server components, CSS Modules with booking tokens), within the signed pictures.
- Secret batching for Koussay's numbered terminal steps.

</decisions>

### Reusable Assets
- `lib/book/*` (config, time, validate, steps, draft, confirmation, research): store-agnostic booking logic; keep and point at D1.

### Established Patterns
- API routes: `json(data, status)` helper, 400 on bad input, bracketed log tags, degrade when not configured (`isXConfigured()` in `lib/env.js`).
- Env read only through `lib/env.js` accessors; on Workers these must read Worker bindings/secrets.
- Best-effort side effects chain `.catch()` with a log (research, draft notice).

### Integration Points
- `lib/notion/bookings.js` exports to replace: `fetchBusyRanges`, `upsertNotionDraft`, `createNotionBooking`, `fillBookingResearch`, `uploadNotionFile`, `clearBusyCache`.

- `app/layout.js` `<SpeedInsights />` → Web Analytics beacon.
- `next.config.mjs` `output: "standalone"` / `VERCEL` checks, `Dockerfile`, `compose.yaml`.
- `tests/smoke.spec.mjs` must run against the Workers build.
