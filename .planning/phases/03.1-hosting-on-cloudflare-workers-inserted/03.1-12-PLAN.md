Request/response contracts (new, used only by the admin controls):
- POST /admin/api/bookings/<id>/status JSON `{ status }` -> 200 `{ ok: true, status, cancelEmail? }`; 409 `{ error }` (re-activate conflict, past-call cancel, or the row changed meanwhile); 400 bad status; 403 no access or cross-origin; 415 non-JSON; 404 unknown id.
- POST /admin/api/bookings/<id>/note JSON `{ note }` (string, trimmed, at most 2,000 characters; empty saves NULL) -> 200 `{ ok: true }`; 400 not a string or too long; 403; 415; 404.
Event write (one batch, D1 rolls back the whole batch on error): `SET_STATUS` = `UPDATE bookings SET status = ?2, updated_at = ?3, cancelled_at = CASE WHEN ?2 = 'cancelled' THEN ?3 ELSE NULL END WHERE id = ?1 AND status = ?4` (?4 = the status read just before, so a concurrent change updates nothing); `INSERT_STATUS_EVENT` = `INSERT INTO booking_events (id, booking_id, at, kind, from_status, to_status) SELECT ?5, ?1, ?3, ?6, ?4, ?2 WHERE EXISTS (SELECT 1 FROM bookings WHERE id = ?1 AND status = ?2 AND updated_at = ?3)` (kind 'cancel' when ?2 = 'cancelled', else 'status'). A unique-index failure on reopen aborts both statements.
Note write: `SET_NOTE` = `UPDATE bookings SET admin_note = ?2, updated_at = ?3 WHERE id = ?1` (updated_at moves so a later Notion re-import, Plan 10, leaves a row Koussay edited untouched; the import never writes admin_note anyway).

| Boundary | Description |
|----------|-------------|

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3.1-42 | Tampering (CSRF) | status and note APIs | mitigate | JSON-only (415 otherwise) and Origin must equal the request origin; cross-site forms cannot send JSON without a preflight the Worker never approves |
| T-3.1-43 | Elevation of privilege | status and note APIs | mitigate | requireAdmin first; 403 tests |
| T-3.1-44 | Tampering | status values, note length | mitigate | Allowlist of four values; note string <= 2000 checked in the route and by a D1 CHECK |
| T-3.1-45 | Tampering (double booking on reopen) | setStatus | mitigate | Unique index raises inside the batch; mapped to 409; no event written; tested |
| T-3.1-46 | Repudiation | cancel email and status history | mitigate | cancel_email_status stored; booking_events row per real change; Resend idempotency key |
| T-3.1-79 | Information disclosure | private note | mitigate | Never in emails, the CSV export or logs; shown only behind requireAdmin with no-store |
