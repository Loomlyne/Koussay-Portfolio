### Booking detail (`/admin/bookings/<id>`)
- Back link `← Bookings` (14px, `--muted`, 44px hit area) returns to the list with the previous `?view=`.
- Header: Name (`--text-title`, weight 500, tracking −0.04em), under it the Dubai-time line (16px) and the visitor-time line (14px `--muted`).
- **Status control** directly under the header, in a `--surface` card:
  - Label "Status" (13px, weight 500, `--muted`).
  - Four-segment control **New · Confirmed · Done · Cancelled** (same segmented style as the view switch, 44px tall, full width on phone). The current status is the selected segment.
  - Choosing New, Confirmed or Done saves at once (JSON POST to `/admin/api/bookings/<id>/status`): all segments disabled while saving; then the message line under the control reads "Saved." (13px, `--muted`, `aria-live="polite"`). On failure the segment snaps back and the message reads the error copy in `--danger`.
  - Choosing Cancelled does not save; it opens the cancel dialog.
  - Cancelled segment is disabled for a call that has already ended; helper under the control: "A past call can't be cancelled. Mark it Done instead." (open item 3).
  - On a cancelled booking, choosing New/Confirmed/Done re-activates it with no email. If the slot was re-booked meanwhile the server answers 409 and the message reads the 409 copy.
- Sections below, each a `--surface` card (`--space-6` padding desktop, `--space-4` phone, `--space-8` between cards), section title 16px weight 500, rows as a `<dl>`: label column 140px 13px `--muted`, value 16px `--ink`, `--space-3` between rows; on phone label stacks above value with `--space-1` gap. Empty values render "—".
  1. **Call** — Date, Time (Dubai), Their time, Length "1 hour", Booked on, Source ("Booking form" or "Imported from Notion").
  2. **Contact** — Name, Email (`mailto:` link), Company, Website (external link, `target="_blank" rel="noopener noreferrer"`, text followed by `↗`).
  3. **Project** — Help with, Budget, Deadline, Details (`white-space: pre-wrap`, full text), Fit checks (the two answers as listed).
  4. **Attachment** — only when one exists: filename (weight 500), size and type in `--muted` ("2.1 MB · PDF"), and one button: **Open file** for image/PDF (opens `/admin/api/files/<id>` in a new tab) or **Download file** for every other type. Secondary button style.
  5. **Research briefing** — by `research_status`:
     - `done`: Summary (paragraph), What they do, Who they serve, "Talking points" bullet list (`callNotes`), "Check on the call" bullet list (`watchOuts`), Sources as external links (hostname text + `↗`). Generated time in `--muted`: "Written 5 Oct, 11:43".
     - `pending`: "Research is still running. Reload in a minute." plus a **Reload** secondary button (`router.refresh()`).
     - `failed`: the stored text ("Couldn't finish the research in time. Open their website before the call.").
     - `none`: "No research for this booking." (imported rows without a briefing, or no research key configured).
  6. **Emails** — Confirmation to visitor, Notice to you, Cancellation (only when cancelled): each "Sent", "Failed" (in `--danger`) or "Skipped". Requires a stored cancel-email result (planner: add `cancel_email_status` to the bookings table; the RESEARCH.md schema has only the visitor/owner columns).

### Blocked time (`/admin/blocks`)
- Title "Blocked time", subline 14px `--muted`: "Blocked hours disappear from the booking form. Times are Dubai time."

  - Segmented **Whole day · Time range** (default Whole day).
  - Whole day: **From** date and **To** date (native date inputs; To defaults to From; To ≥ From). Blocks every slot of each day in Asia/Dubai.
  - Time range: **Date**, **From** select (09:00 … 19:00, hourly), **To** select (10:00 … 20:00, hourly, must be after From).
  - **Note** — optional text input, max 80 characters, placeholder "Only you see this".
  - **Block time** — primary solid button.
  - Inputs: 48px tall, 16px text (no iOS zoom), 1px `--control-border`, `--radius-item`, focus border `--control-border-focus` plus `--focus-ring`.
  - Inline validation under the field in `--danger` 13px; the button stays enabled and the server re-validates.
  - Past dates are rejected ("Pick today or a later date.").

- Past blocks are not listed.
- Phone: form fields full width, stacked; list rows become cards with Remove full width.

## `.ics` Invite Contract (owner email only)

Hand-written RFC 5545 builder (`lib/mail/ics.mjs`, RESEARCH.md Pattern 12): CRLF, lines folded at 75 octets, TEXT escaping, UTC times with `Z`, no `VTIMEZONE`.

| Property | Value |
|----------|-------|
| Filename / type | `invite.ics` / `text/calendar; charset=utf-8; method=PUBLISH` |
| `METHOD` | `PUBLISH` (his own calendar entry, not an invitation to answer) |
| `PRODID` | `-//koussay.online//bookings//EN` |
| `UID` | `booking-<id>@koussay.online` (stable, so a re-sent invite updates rather than duplicates) |
| `DTSTAMP` | send time, UTC |
| `DTSTART` / `DTEND` | `slot_start` / `slot_end` in UTC (1 hour) |
| `SUMMARY` (title) | `Call — {Name}, {Company}`; company empty → `Call — {Name}` |
| `DESCRIPTION` | lines, `\n`-joined: `{Name} <{email}>` · `Company: …` · `Website: …` · `Help with: …` · `Budget: …` · `Deadline: …` · `Their time: {09:00} {London/GMT}` · blank · `Details:` + details (cut at 1,000 characters with `…`) · blank · `Admin: https://koussay.online/admin/bookings/<id>`. Empty fields are left out, never "—" |
